Modul 1 · Arbeitsheft

Zwei Rechner direkt verbinden

Lernziel: Du baust ein Peer-to-Peer-Netz und prüfst die Verbindung mit ping.

Denke daran
Zwei Geräte können direkt miteinander verbunden werden. Damit IPv4-Kommunikation funktioniert, müssen beide Adressen im selben Netz liegen und eindeutig sein.

Du brauchst

  • Projekt aus Modul 0
  • Zwei Rechner oder Notebooks

Aufgabe

  1. Platziere zwei Rechner. Benenne sie Rechner 10 und Rechner 11.
  2. Verbinde die Rechner mit einem Kabel.
  3. Setze 192.168.10.10 und 192.168.10.11 mit der Subnetzmaske 255.255.255.0.
  4. Starte die Simulation. Installiere auf Rechner 10 CMD und führe ping 192.168.10.11 aus.
  5. Öffne zusätzlich die Paket-/Datenaustauschansicht. Welche Nachrichten siehst du?

Beim ersten Ping kann vor der Echo-Anfrage eine Auflösung der Zieladresse sichtbar werden. Danach folgen Echo request und Echo reply.

Modul 2 · Arbeitsheft

Ein Switch verbindet ein LAN

Lernziel: Du erweiterst das Netz, beobachtest Lernen von MAC-Adressen und erklärst LAN und Protokoll.

Denke daran
Ein Switch verbindet mehrere Geräte im selben lokalen Netz. Er lernt, an welchem Port eine Quell-MAC-Adresse erreichbar ist, und leitet Frames gezielter weiter.

Du brauchst

  • Projekt aus Modul 1
  • Einen Switch und einen dritten Rechner

Aufgabe

  1. Platziere einen Switch und einen dritten Rechner namens Server 12.
  2. Verbinde alle drei Rechner mit dem Switch. Lass die Adressen im Netz 192.168.10.0/24.
  3. Starte die Simulation und sende von Rechner 10 einen Ping an Rechner 12.
  4. Sende danach von Rechner 11 einen Ping an Rechner 12. Vergleiche die Paketansichten.
  5. Beschreibe, was im Alltag einem Switch entspricht, wenn man an ein Stromnetz denkt.

Modul 3 · Arbeitsheft

Client und Server

Lernziel: Du untersuchst einen Dienst und trennst Client, Serverprogramm und Servergerät.

Denke daran
Ein Client fordert einen Dienst an. Ein Serverprogramm bietet ihn an. Ein Computer wird oft ebenfalls Server genannt, wenn er solche Programme bereitstellt.

Du brauchst

  • Projekt aus Modul 2
  • CMD, Echo-Server, Einfacher Client

Aufgabe

  1. Installiere auf Server 12 den Echo-Server und starte ihn auf Port 55555.
  2. Installiere auf Rechner 10 den Einfachen Client und verbinde ihn mit 192.168.10.12:55555.
  3. Sende drei Nachrichten. Beobachte Antwort, Quelle, Ziel und Port in der Paketansicht.
  4. Erkläre mit eigenen Worten, was der Echo-Server leistet.
  5. Übertrage das Prinzip auf Webserver, Dateiserver und Mailserver.

Modul 4 · Arbeitsheft

Zwei Netze mit einem Router verbinden

Lernziel: Du unterscheidest Netzadresse, Gateway und Router und findest einen Konfigurationsfehler.

Denke daran
Ein Router verbindet unterschiedliche IP-Netze. Ein Gerät schickt Ziele außerhalb seines eigenen Netzes an das Standardgateway.

Du brauchst

  • Projekt aus Modul 3
  • Router/Vermittlungsrechner, zweiter Switch, drei weitere Rechner

Aufgabe

  1. Baue ein zweites LAN mit 192.168.20.0/24 und den Geräten Client 20 (192.168.20.10) und Client 21 (192.168.20.11).
  2. Platziere einen Router mit zwei Schnittstellen. Verwende 192.168.10.1 und 192.168.20.1.
  3. Teste aus dem ersten LAN einen Ping zu 192.168.20.10 ohne Gateway. Notiere das Ergebnis.
  4. Setze das Gateway der Geräte im ersten LAN auf 192.168.10.1 und im zweiten LAN auf 192.168.20.1.
  5. Teste erneut und erkläre, warum sich das Ergebnis ändert.

Modul 5 · Arbeitsheft

Das eigene Web: Server und Browser

Lernziel: Du stellst eine lokale HTML-Seite bereit und rufst sie über den Webbrowser ab.

Denke daran
Der Webserver ist ein Dienst. Der Webbrowser ist sein Client. Eine Webseite besteht aus HTML und kann weitere Dateien anfordern.

Du brauchst

  • Projekt aus Modul 4
  • Datei-Explorer, Texteditor, Webserver, Webbrowser

Aufgabe

  1. Installiere auf Server 12 den Datei-Explorer, den Texteditor und den Webserver.
  2. Öffne die vorhandene Datei /www/index.html im Texteditor und ersetze sie durch eine eigene Seite mit Überschrift, Absatz und Link.
  3. Lege mit dem Datei-Explorer im Ordner /www zusätzlich kontakt.html an und bearbeite die Datei anschließend im Texteditor.
  4. Starte den Webserver. Installiere auf Client 20 den Webbrowser.
  5. Öffne im Browser http://192.168.10.12. Beobachte die HTTP-Anfrage und -Antwort.

Modul 6 · Arbeitsheft

DNS: Namen statt Zahlen

Lernziel: Du richtest einen DNS-Eintrag ein und rufst die Webseite mit einem Namen auf.

Denke daran
DNS ordnet einen Hostnamen einer IP-Adresse zu. Der Browser kann dadurch einen Namen nutzen, obwohl die Kommunikation weiterhin eine IP-Adresse benötigt.

Du brauchst

  • Projekt aus Modul 5
  • DNS-Server auf einem neuen Server im ersten LAN

Aufgabe

  1. Platziere DNS 53 im ersten LAN mit 192.168.10.53 und Gateway 192.168.10.1.
  2. Trage bei den Rechnern den DNS-Server 192.168.10.53 ein.
  3. Installiere und starte den DNS-Server auf DNS 53.
  4. Lege den Eintrag www.filius.test → 192.168.10.12 an.
  5. Öffne im Browser http://www.filius.test und vergleiche die Anfrage mit dem direkten Aufruf über die IP-Adresse.
  6. Markiere in www.filius.test Root, Top-Level-Domain, Second-Level-Domain und Hostname.

Modul 7 · Arbeitsheft

Automatik und Pakete

Denke daran
DHCP kann Netzwerkkonfiguration automatisch vergeben. Paketorientierte Übertragung zerlegt eine Kommunikation in einzelne Nachrichten mit Quelle, Ziel, Protokoll und Dienst.

Du brauchst

  • Projekt aus Modul 6
  • DHCP-Server oder Paketansicht

Aufgabe

  1. Vergleiche eine fest eingetragene IP-Konfiguration mit einem DHCP-Client.
  2. Richte einen DHCP-Server für 192.168.20.0/24 ein oder öffne die vorhandene DHCP-Funktion.
  3. Aktiviere die automatische Konfiguration auf einem Client und notiere den erhaltenen Lease.
  4. Lade die Webseite erneut und notiere mindestens fünf Paketzeilen: Quelle, Ziel, Protokoll oder Dienst, Beobachtung.
  5. Erkläre, warum eine Datei nicht als ein einziger unteilbarer Block übertragen werden muss.

Modul 8 · Arbeitsheft

Abschluss: Dein kleines Internet

Lernziel: Du planst, baust und erklärst eine eigene vernetzte Anwendung.

Denke daran
Ein Netz ist ein Zusammenspiel aus Geräten, Adressen, Weiterleitung, Namensauflösung und Anwendungen. Gute Netzplanung macht jeden Weg nachvollziehbar.

Du brauchst

  • Die bisherigen Projektdateien
  • Skizzenpapier oder Notiz-App
  • FiliusPad

Aufgabe

  1. Plane zwei LANs mit mindestens vier Endgeräten, einem Switch, einem Router, einem DNS-Server und einem Webserver.
  2. Lege einen Adressplan mit Netzmaske, Gateway und DNS fest.
  3. Baue die Topologie in FiliusPad und speichere sie unter 260805-09-Abschluss-Name.fls.
  4. Beweise drei Dinge: Ping über den Router, Webzugriff über IP, Webzugriff über DNS-Namen.
  5. Exportiere oder zeichne eine Dokumentation mit Topologie, Adressplan, Paketbeobachtung und Fehlerfall.
  6. Schreibe eine Reflexion: Welche Konfiguration war notwendig, damit der Name bis zur Webseite führte?

Nachschlagen

Glossar

Adresse
Eine Kennzeichnung, mit der ein Ziel im Netz gefunden wird.
DNS
Ordnet Namen wie www.filius.test IP-Adressen zu.
Gateway
Der nächste Router für Ziele außerhalb des eigenen Netzes.
IP-Adresse
Logische Adresse eines Geräts in einem IP-Netz.
LAN
Local Area Network, ein lokales Rechnernetz.
MAC-Adresse
Hardware-nahe Adresse einer Netzwerkschnittstelle.
Port
Nummer, die einen Dienst auf einem Gerät unterscheidet.
Protokoll
Vereinbarte Regeln und Nachrichtenformate.
Router
Vermittelt Daten zwischen verschiedenen Netzen.
Server
Ein Programm, das einen Dienst anbietet; oft auch das Gerät, auf dem es läuft.
Switch
Verbindet mehrere Geräte in einem LAN und leitet Frames weiter.
Fehler-Checkliste
Simulation läuft? Kabel verbunden? IP und Maske korrekt? Gateway gesetzt? DNS eingetragen? Dienst gestartet? Ziel und Port richtig?
